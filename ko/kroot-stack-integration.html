KRoot 통합 설치와 사용 가이드 ​

이 문서는 kroot-adk, kroot-server, kroot-proto를 한 세트로 설치하고 실제로 사용하는 방법을 정리한 안내서입니다.

세 저장소는 역할이 분리되어 있습니다. kroot-proto는 API 계약, kroot-server는 중앙 백엔드, kroot-adk는 개발자 PC에서 쓰는 CLI와 Claude Code 템플릿을 담당합니다.

전체 구조 ​

text
개발자 PC
  kroot-adk
    - kroot CLI
    - Claude Code templates/hooks/skills/agents
    - .mcp.json
      |
      | gRPC + JWT
      v
kroot-server
  - gRPC API :4500
  - REST health/check API :4501
  - MCP Gateway :8600
      |
      v
PostgreSQL + S3/MinIO

공유 API 계약
  kroot-proto
저장소역할실행 여부
kroot-protogRPC proto와 생성 코드의 단일 출처직접 실행하지 않음
kroot-serverDB/S3에 접근하는 백엔드 서버, MCP Gateway 포함서버로 실행
kroot-adk개발자 CLI, Claude Code 템플릿, hooks, stage 명령개발자 PC에서 실행

로컬 DB를 처음 만드는 경우에는 kroot-ui-refctoring의 Prisma migration도 필요합니다. KRoot의 핵심 실행 세트는 위 세 저장소이지만, 현재 DB schema 소유권은 UI 저장소에 있기 때문입니다.

어떤 설치가 필요한가요? ​

상황필요한 것
팀 서버에 붙어서 CLI만 사용kroot-adk 설치, 서버 주소, 계정
로컬에서 전체 스택 개발kroot-proto, kroot-server, kroot-adk, PostgreSQL, MinIO
Claude Code에서 MCP까지 사용위 구성에 kroot-mcp-gateway 실행
Claude.ai Custom Connector 사용공개 도메인, HTTPS 프록시, kroot-mcp-gateway 운영 배포

처음 시작할 때는 팀 서버에 CLI만 붙이는 방식이 가장 간단합니다. 서버나 proto를 개발해야 할 때만 로컬 전체 스택을 준비하면 됩니다.

준비 사항 ​

  • Go 1.25 이상
  • Docker와 Docker Compose
  • Git
  • Node.js와 npm: 빈 DB에 Prisma migration을 적용할 때 필요합니다.
  • Buf CLI: proto를 수정하고 생성 코드를 갱신할 때 필요합니다.
  • Claude Code: KRoot agent, skill, hook을 실제 프로젝트에서 사용할 때 필요합니다.

1. 저장소 배치 ​

로컬 전체 스택은 세 저장소를 같은 상위 폴더에 형제 디렉터리로 두는 것을 기준으로 합니다. 두 Go 모듈이 개발 중 ../kroot-proto를 참조하기 때문입니다.

bash
mkdir -p ~/Dev/Business/kaonsoftlab
cd ~/Dev/Business/kaonsoftlab

git clone https://github.com/kslaboratory/kroot-proto.git
git clone https://github.com/kslaboratory/kroot-server.git
git clone https://github.com/kslaboratory/kroot-adk.git

필요하면 UI 저장소도 같은 위치에 둡니다.

bash
git clone <kroot-ui-refctoring-repo-url> kroot-ui-refctoring

최종 구조는 다음처럼 됩니다.

text
kaonsoftlab/
  kroot-proto/
  kroot-server/
  kroot-adk/
  kroot-ui-refctoring/

2. kroot-proto 확인 ​

kroot-proto는 실행 서버가 아닙니다. API 계약과 생성 코드를 보관하는 저장소입니다.

기본 확인은 다음 정도면 충분합니다.

bash
cd ~/Dev/Business/kaonsoftlab/kroot-proto
ls proto/kroot/v1
ls gen/kroot/v1

proto를 수정했을 때만 생성 코드를 갱신합니다.

bash
buf generate

변경 후에는 소비자 저장소도 같이 확인합니다.

bash
cd ../kroot-adk
go test ./...

cd ../kroot-server
go test ./...

실무 팁은 간단합니다. proto는 가장 바깥쪽 계약이므로 필드 삭제, 번호 변경, 서비스명 변경은 영향이 큽니다. 새 필드를 추가하는 방향이 가장 안전하고, 깨지는 변경은 반드시 서버와 ADK를 함께 수정한 뒤 검증해야 합니다.

3. kroot-server 로컬 실행 ​

로컬에서 서버를 개발하거나 전체 흐름을 확인하려면 먼저 PostgreSQL과 MinIO를 실행합니다.

bash
cd ~/Dev/Business/kaonsoftlab/kroot-server
docker compose up -d postgres minio

기본 접속 정보는 다음과 같습니다.

항목값
PostgreSQLlocalhost:5432
Databasekroot_dev
DB 사용자kroot / kroot
MinIO S3 APIlocalhost:9000
MinIO 콘솔http://localhost:9001
MinIO 계정minioadmin / minioadmin123

빈 DB라면 Prisma migration을 먼저 적용합니다.

bash
cd ../kroot-ui-refctoring
DATABASE_URL="postgres://kroot:kroot@localhost:5432/kroot_dev?sslmode=disable" \
  npx prisma migrate deploy

다시 서버 저장소로 돌아와 로컬 환경 파일을 만듭니다.

bash
cd ../kroot-server
cp secrets.env.example .env.local

.env.local의 핵심 값은 로컬 Docker 설정과 맞춰 둡니다.

dotenv
KROOT_DB_URL=postgres://kroot:kroot@localhost:5432/kroot_dev?sslmode=disable
KROOT_JWT_SECRET=replace-with-32-or-more-random-bytes
KROOT_S3_ENDPOINT=localhost:9000
KROOT_S3_ACCESS_KEY=minioadmin
KROOT_S3_SECRET_KEY=minioadmin123
KROOT_S3_BUCKET=kroot-files
KROOT_S3_USE_SSL=false

서버를 실행합니다.

bash
go run ./cmd/kroot-server

다른 터미널에서 상태를 확인합니다.

bash
curl http://127.0.0.1:4501/healthz
curl http://127.0.0.1:4501/readyz

/readyz가 {"status":"ready","db":"ok"} 형태로 응답하면 DB 연결까지 정상입니다. CLI가 접속할 gRPC 주소는 grpc://127.0.0.1:4500입니다.

운영 배포와 MCP Gateway 상세 설치는 kroot-server/docs/install.md와 kroot-server/docs/mcp-gateway-deployment.md를 함께 보면 됩니다.

4. kroot-adk 설치 ​

개발자 PC에서는 kroot CLI가 필요합니다. 설치 방법은 세 가지가 있습니다.

4.1 설치 스크립트 ​

일반 사용자는 설치 스크립트가 가장 간단합니다.

bash
curl -fsSL https://kslaboratory.github.io/kroot-docs/install.sh | bash

전역 경로에 설치하려면 다음처럼 실행합니다.

bash
curl -fsSL https://kslaboratory.github.io/kroot-docs/install.sh | bash -s -- --global

설치 확인은 이렇게 합니다.

bash
kroot --version
kroot doctor

4.2 go install ​

Go 환경이 준비되어 있다면 go install도 사용할 수 있습니다.

bash
go install github.com/kslaboratory/kroot-adk/cmd/kroot@latest

다만 로컬에서 kroot-adk와 kroot-proto를 함께 수정하는 개발 중이라면, 아래 소스 빌드 방식이 더 정확합니다.

4.3 소스 빌드와 설치 ​

bash
cd ~/Dev/Business/kaonsoftlab/kroot-adk
make build

make build는 저장소 안에 dist/kroot만 만듭니다. 터미널 어디서나 쓰려면 make install을 실행합니다.

bash
make install

차이는 다음과 같습니다.

명령결과주 용도
make builddist/kroot 생성빌드 확인, 저장소 안에서 임시 실행
make installGOBIN에 kroot, kroot-wt 설치개발자 PC에 실제 CLI 설치

설치 위치를 직접 정하고 싶다면 GOBIN을 넘깁니다.

bash
make install GOBIN="$HOME/.local/bin"

PATH도 확인합니다.

bash
export PATH="$HOME/.local/bin:$(go env GOPATH)/bin:$PATH"
kroot --version

5. 서버 로그인 ​

로컬 서버에 붙을 때는 서버 주소를 환경 변수로 지정합니다.

bash
export KROOT_SERVER=grpc://127.0.0.1:4500

팀 서버를 쓴다면 팀에서 받은 주소로 바꾸면 됩니다.

bash
export KROOT_SERVER=grpc://kroot.example.com:4500

로그인합니다.

bash
kroot auth login --server "$KROOT_SERVER" --email pm@example.com
kroot auth whoami

kroot auth login은 새 사용자를 생성하지 않습니다. 웹 UI나 seed로 이미 만들어진 사용자를 검증하고, 토큰을 ~/.kroot/credential.json에 저장합니다.

토큰 상태만 로컬에서 보려면 다음 명령을 씁니다.

bash
kroot auth status

6. 프로젝트 초기화와 서버 연결 ​

KRoot를 사용할 실제 프로젝트 폴더에서 kroot init을 실행합니다.

bash
cd /path/to/my-project
kroot init --server "$KROOT_SERVER" --locale ko

이 명령은 프로젝트에 Claude Code용 템플릿, hooks, skill, agent, .mcp.json, .kroot 설정을 설치합니다.

이미 서버에 있는 프로젝트와 연결하려면 --project-id를 함께 넘깁니다.

bash
kroot init --server "$KROOT_SERVER" --project-id <project-id> --locale ko

이미 로컬 초기화가 끝난 폴더라면 kroot link만 실행해도 됩니다.

bash
# 기존 원격 프로젝트에 연결
kroot link --server "$KROOT_SERVER" --project <project-id>

# 서버에 새 프로젝트를 만들고 현재 폴더와 연결
kroot link --server "$KROOT_SERVER" --create --name "Demo Project"

# 현재 연결 상태 확인
kroot link status

연결 정보는 프로젝트 안의 .kroot/project.json에 저장됩니다. 이후 hooks와 stage CLI는 이 값을 기준으로 대화, 세션, 산출물, 단계별 카드를 kroot-server에 동기화합니다.

템플릿만 최신 버전으로 다시 동기화하려면 다음 명령을 사용합니다.

bash
kroot update --sync-templates

이 명령은 설치된 프로젝트의 .claude, .kroot, .mcp.json 같은 템플릿 파일을 현재 ADK에 포함된 최신 템플릿 기준으로 갱신할 때 사용합니다.

7. 워크플로우 선택과 단계 검증 ​

KRoot Pipeline은 S00부터 S12까지의 단계로 움직입니다. 하지만 모든 단계가 항상 실행되는 것은 아닙니다. 서버의 프로젝트 워크플로우 테이블에 활성화된 단계만 실행해야 합니다.

먼저 프로젝트의 워크플로우를 확인합니다.

bash
kroot workflow list

사용할 워크플로우를 선택합니다.

bash
kroot workflow select <workflow-id>
kroot workflow current

선택 결과는 .kroot/active-workflow.json에 저장됩니다. 이후 stage 명령과 Claude Code pipeline skill은 이 파일을 기준으로 어떤 워크플로우에 산출물을 저장할지 결정합니다.

활성 단계 목록을 확인합니다.

bash
kroot workflow stage list

특정 단계가 실행 가능한지 검증합니다.

bash
kroot workflow stage validate S01
kroot workflow stage validate S01 --json

검증에 실패하면 해당 단계 agent는 실행되면 안 됩니다. 예를 들어 사용자가 “S01 단계 실행해줘”라고 했더라도 서버 테이블에 S01이 활성 상태로 없으면 “현재 단계가 활성화되지 않았습니다”라고 알려주고 멈추는 것이 맞습니다.

8. Claude Code에서 사용하는 흐름 ​

프로젝트 초기화와 서버 연결이 끝났다면 Claude Code를 프로젝트 루트에서 실행합니다.

bash
cd /path/to/my-project
claude

일반적인 사용 흐름은 다음과 같습니다.

text
KRoot Pipeline으로 새 프로젝트 시작해줘.
S01 요구사항 분석 단계 실행해줘.
S09 프론트엔드 구현 단계 실행해줘.
S10 백엔드 구현 단계 실행해줘.

Claude Code 안의 kroot-workflow-pipeline skill은 단계 실행 전에 kroot workflow stage validate SNN --json으로 활성 단계를 확인해야 합니다. 단계가 활성화되어 있지 않으면 agent를 실행하지 않고 사용자에게 상태를 설명해야 합니다.

stage 산출물은 단계별 CLI와 hook을 통해 서버에 저장됩니다.

단계대표 CLI
S00kroot init-version ...
S01kroot requirement-version ...
S02kroot spec-version ...
S03kroot erd-version ...
S04kroot wireframe ...
S05kroot usecase-stage ...
S06kroot event-storming ...
S07kroot design ...
S08kroot html-stage ...
S09kroot frontend-stage ...
S10kroot backend-stage ...
S11kroot test-stage ...

각 명령의 상세 옵션은 kroot <command> --help로 확인합니다.

9. MCP Gateway 사용 ​

MCP를 사용하려면 kroot-server의 별도 바이너리인 kroot-mcp-gateway를 실행합니다.

로컬 Claude Code용 테스트는 다음처럼 할 수 있습니다.

bash
cd ~/Dev/Business/kaonsoftlab/kroot-server
go run ./cmd/kroot-mcp-gateway \
  --http 127.0.0.1:8600 \
  --issuer-url http://127.0.0.1:8600

상태를 확인합니다.

bash
curl http://127.0.0.1:8600/healthz
curl -s http://127.0.0.1:8600/.well-known/oauth-authorization-server

Claude Code는 kroot auth login으로 받은 CLI JWT를 MCP Bearer token으로 재사용할 수 있습니다.

bash
export KROOT_MCP_URL=http://127.0.0.1:8600/mcp
export KROOT_JWT="$(kroot auth token)"
claude

프로젝트의 .mcp.json은 기본적으로 다음 형태를 사용합니다.

json
{
  "mcpServers": {
    "kroot": {
      "type": "http",
      "url": "${KROOT_MCP_URL:-http://localhost:8600/mcp}",
      "headers": {
        "Authorization": "Bearer ${KROOT_JWT}"
      }
    }
  }
}

Claude.ai Custom Connector로 연결하려면 localhost가 아니라 공개 HTTPS 주소가 필요합니다. 운영 설치는 kroot-server/docs/mcp-gateway-deployment.md를 기준으로 진행합니다.

10. 변경 작업 순서 ​

세 저장소를 함께 수정할 때는 순서가 중요합니다.

proto를 바꾸는 경우 ​

bash
cd ../kroot-proto
buf generate

cd ../kroot-server
go test ./...

cd ../kroot-adk
go test ./...

proto 변경은 서버와 ADK 양쪽에 영향을 줍니다. 그래서 kroot-proto를 먼저 갱신하고, 그 다음 kroot-server, 마지막으로 kroot-adk를 맞추는 순서가 안전합니다.

서버 기능을 바꾸는 경우 ​

bash
cd ../kroot-server
go test ./...
go build -o bin/kroot-server ./cmd/kroot-server
go build -o bin/kroot-mcp-gateway ./cmd/kroot-mcp-gateway

MCP 도구나 prompt 계약을 바꿨다면 ADK의 agent 산출물 계약도 같이 확인합니다.

bash
cd ../kroot-adk
python3 scripts/check_stage_contracts.py --server-root ../kroot-server

ADK 템플릿이나 CLI를 바꾸는 경우 ​

bash
cd ../kroot-adk
make test
make build
make check-stage-contracts

로컬 프로젝트에 새 템플릿을 반영합니다.

bash
kroot update --sync-templates

11. 주요 파일 위치 ​

위치설명

<project>/.kroot/project.json로컬 폴더와 서버 프로젝트 연결 정보
<project>/.kroot/active-workflow.json현재 선택된 프로젝트 워크플로우
<project>/.claude/settings.jsonClaude Code hook 설정
<project>/.mcp.jsonClaude Code MCP 서버 설정
kroot-server/.env.local로컬 서버 환경 변수
kroot-proto/proto/kroot/v1proto 원본
kroot-proto/gen/kroot/v1생성된 Go 코드

자주 보는 문제 ​

증상확인할 것
kroot: command not found~/.local/bin 또는 $(go env GOPATH)/bin이 PATH에 있는지 확인합니다.
KROOT_DB_URL is requiredkroot-server를 저장소 루트에서 실행했는지, .env.local에 값이 있는지 확인합니다.
/readyz 실패PostgreSQL 실행 여부, Prisma migration 적용 여부, KROOT_DB_URL 값을 확인합니다.
invalid email or password웹 UI나 seed로 사용자가 먼저 생성되어 있는지 확인합니다.
not signed inkroot auth login --server "$KROOT_SERVER"를 먼저 실행합니다.
this directory is not linked프로젝트 루트에서 kroot init 또는 kroot link를 실행합니다.

빠른 실행 요약 ​

로컬 전체 스택을 한 번에 확인하는 최소 흐름은 다음과 같습니다.

bash
# 1. 저장소 배치
cd ~/Dev/Business/kaonsoftlab
git clone https://github.com/kslaboratory/kroot-proto.git
git clone https://github.com/kslaboratory/kroot-server.git
git clone https://github.com/kslaboratory/kroot-adk.git

# 2. 서버 인프라
cd kroot-server
docker compose up -d postgres minio
cp secrets.env.example .env.local
# .env.local 값을 로컬 DB/MinIO에 맞게 수정
go run ./cmd/kroot-server

# 3. ADK 설치
cd ../kroot-adk
make install
export KROOT_SERVER=grpc://127.0.0.1:4500
kroot auth login --server "$KROOT_SERVER" --email pm@example.com

# 4. 프로젝트 연결
cd /path/to/my-project
kroot init --server "$KROOT_SERVER" --locale ko
# 원격 프로젝트가 아직 연결되지 않았다면 새로 만들고 연결
kroot link --server "$KROOT_SERVER" --create --name "Demo Project"
kroot workflow list
kroot workflow select <workflow-id>
kroot workflow stage list

# 5. Claude Code 실행
claude

이 흐름이 정상이라면, 이후부터는 Claude Code에서 KRoot Pipeline을 요청하고 각 단계 산출물이 kroot-server에 저장되는지 확인하면 됩니다.

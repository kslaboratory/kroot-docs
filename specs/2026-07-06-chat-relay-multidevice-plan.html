Chat Relay 멀티디바이스 (테이블 + 브라우저 기기 선택기) ​

작성일: 2026-07-06 · 상태: 구현 완료 (relay·client·frontend, 미배포)

배경 / 문제 ​

현재 relay는 user당 agent 1개만 지원한다(agents map[string]Sender). 같은 계정으로 두 기기(맥북·윈도우)가 kroot chat start 하면 r.agents[user] = s로 나중 연결이 이전 연결을 조용히 덮고, 진 기기는 ws가 열려 있어도(“연결됨” 표시) 브라우저 요청을 못 받는 조용한 먹통이 된다. auto-reconnect까지 겹치면 슬롯 다툼이 반복된다.

참고: /Users/jikime/Dev/Private/cli-relay는 아직 동일한 single-agent 구조지만, 발급 JWT가 {sub, deviceId}를 담고 클라이언트 credential이 deviceId를 저장한다 — 멀티디바이스의 재료만 준비된 상태.

목표 ​

같은 계정의 여러 기기를 동시 연결로 유지하고, relay가 기기 테이블로 관리하며, 브라우저(웹 채팅)가 기기 목록을 보고 대상 기기를 골라 프롬프트를 그 기기에서 실행한다.

프로토콜 변경 ​

1) agent 레그 — 기기 식별자 전달 ​

  • 연결 URL에 쿼리 추가: /ws/agent?device=<deviceID>&label=<hostname> (Bearer PAT는 그대로 userID 해석).
  • device 없으면(구버전) relay가 연결당 유니크 ID를 부여하고 label을 “기기(구버전)”로 → 하위호환.

2) relay → browser — 기기 로스터 푸시 ​

  • 신규 메시지: {"type":"agent:devices","devices":[{"id","label","connectedAt"}]}
  • 기기 연결/해제 시 해당 user의 모든 browser로 푸시. browser 접속 즉시 현재 로스터 1회 전송.
  • 기존 {"type":"agent:status","connected":bool}는 connected = len(devices)>0으로 유지(하위호환).

3) browser → relay — 대상 기기 지정 ​

  • 프롬프트 JSON에 targetDeviceId 필드 추가.
  • relay 라우팅:
    • targetDeviceId 있고 존재 → 그 기기로 전달.
    • 없음 + 기기 1개 → 그 기기(하위호환). 없음 + 여러 개 → 가장 최근 연결 기기로 전달(UI 기본선택과 일치).
    • targetDeviceId 지정됐으나 오프라인 → {"type":"agent:unavailable","reason":"device-offline","deviceId":…}.
  • 전달은 원본 바이트 그대로(executor는 미지 필드 무시). relay는 라우팅 위해 JSON에서 targetDeviceId만 peek.

컴포넌트별 변경 ​

A. kroot-server (relay) — internal/relay/ ​

  • registry.go: agents map[string]map[string]agentEntry (user→deviceID→{sender,label,connectedAt}).
    • RegisterAgent(user, deviceID, label, sender) unregister — 같은 deviceID 재등록은 그 기기 갱신.
    • DevicesFor(user) []DeviceInfo, AgentFor(user, deviceID) (Sender,bool), MostRecentAgent(user).
  • server.go:
    • handleAgent: 쿼리에서 device/label 파싱 → RegisterAgent. connect/disconnect 시 notifyDevices(user).
    • handleBrowser: 접속 시 로스터 전송. 수신 메시지에서 targetDeviceId peek → 라우팅.
    • agent:status는 로스터 유무로 계속 전송(하위호환).
  • 테스트: registry 다중기기 등록/해제/최근선택, server 라우팅(대상 지정/미지정/오프라인).

B. kroot-adk (client) — internal/krootauth, internal/chatagent, cmd/chatcmd ​

  • credential.go: DeviceID string json:"deviceId,omitempty" 추가 + EnsureDeviceID()(최초 1회 uuid 생성·저장).
  • chatagent/agent.go: relayURL에 ?device=&label= 부착(기존 쿼리 보존, url.Parse 사용). Run 시그니처에 deviceID·label 추가 또는 start.go에서 URL 구성.
  • cmd/chatcmd/start.go: EnsureDeviceID() 호출, os.Hostname()을 label로 전달.

C. kroot-main-site (frontend) — 구현됨 ​

  • src/shared/contexts/WebSocketContext.tsx:
    • RelayDevice 타입 export. onmessage에 agent:devices 처리 → devices[] 상태, selectedDeviceId(유효하면 유지, 아니면 최근=마지막 기기). 소켓 close 시 로스터 초기화. 컨텍스트에 devices, selectedDeviceId, setSelectedDeviceId 노출.
    • 중앙 주입(개선): 개별 송신부를 고치는 대신 sendMessage에서 targetDeviceId를 모든 메시지에 자동 첨부한다. chat뿐 아니라 permission_response·abort·skills_list도 같은 기기로 라우팅돼야 하는데, relay가 browser→agent 전 메시지를 target으로 라우팅하므로 한 곳에서 주입하는 게 정확하고 안전. (선택값은 selectedDeviceIdRef로 stale-closure 회피.)
  • 기기 드롭다운 UI: features/shell/ui/navigation/status-bar.tsx — 채팅 활성 + 기기≥2면 <select>, 1개면 라벨.
  • stores/agents/chat-link-store.ts: 트리 밖 StatusBar용으로 devices/selectedDeviceId/selectDevice 추가, provider가 publish + setSelector 주입.
  • ticket(relay-ticket)은 user 단위라 변경 없음.

하위호환 / 롤아웃 ​

  • 구버전 클라이언트(device 미전송) → “기기(구버전)” 단일 기기로 정상 동작.
  • 구버전 프론트(targetDeviceId 미전송) → 기기 1개면 그대로, 여러 개면 최근 기기로 라우팅.
  • 릴레이 먼저 배포 → 프론트 → 클라이언트 순서 무관(각 단계 하위호환).

미결/후순위 ​

  • agent→browser 이벤트에 sourceDeviceId 태깅(멀티탭 교차 스트림 필터) — v1은 기존처럼 전체 팬아웃.
  • 기기 이름 사용자 지정(현재 hostname 라벨).

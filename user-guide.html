사용자 설치 가이드 ​

이 문서는 실습 환경을 준비하기 위해 Git Bash · Node.js · Claude Code 세 가지를 설치하는 방법을 안내한다. Windows와 Mac을 모두 다루며, 각 도구의 상세 설치 화면은 별도 가이드 문서로 분리되어 있다.

출처: 이 가이드의 설치 절차와 화면은 각 도구의 공식 문서 및 설치 안내 블로그를 크롤링해 정리했다. 원본 링크는 각 상세 가이드 안에 명시되어 있다.

설치 대상 한눈에 보기 ​

도구무엇인가WindowsMac상세 가이드
Git BashWindows에서 git, ls, cd 등을 편하게 쓰는 터미널 환경필요불필요(기본 git 제공)git-bash-install.md
Node.jsnpm을 제공하는 자바스크립트 런타임. Claude Code 설치에 필요필요필요nodejs-install.md
Claude Code터미널에서 사용하는 Anthropic 공식 CLI필요필요claude-code-install.md

설치 순서 ​

설치는 의존성 순서대로 진행한다.

  1. Git Bash (Windows만 해당) — Windows에서 일관된 터미널 환경을 먼저 마련한다. Mac은 건너뛴다.
  2. Node.js — npm을 설치한다. Windows·Mac 공통으로 필요하다.
  3. Claude Code — npm으로 설치한다.
[Windows] Git Bash → Node.js → Claude Code
[Mac]              Node.js → Claude Code

1. Git Bash (Windows 전용) ​

Windows에서는 git, ls, cd, mkdir 같은 명령을 편하게 쓰기 위해 Git Bash를 설치한다. Mac은 Git이 기본 제공되므로 터미널에서 git --version으로 확인만 하면 된다.

  • 공식 다운로드: https://git-scm.com
  • 상세 설치 화면 16단계 → Git Bash 설치 가이드

설치 후 확인:

bash
git --version

2. Node.js (Windows / Mac 공통) ​

Node.js를 설치하면 함께 제공되는 npm을 사용할 수 있다. Claude Code를 npm으로 설치하므로 반드시 필요하다. 처음 설치하는 사람은 LTS 버전을 선택한다.

  • 공식 다운로드: https://nodejs.org/ko
  • Windows · Mac(pkg) · Mac(Homebrew) 설치 화면 → Node.js 설치 가이드

Mac에서 Homebrew를 쓴다면 한 줄로 설치할 수도 있다.

bash
brew install node

설치 후 확인:

bash
node -v
npm -v

3. Claude Code (Windows / Mac 공통) ​

Node.js가 준비되면 npm으로 Claude Code를 전역 설치한다. Windows는 Git Bash 터미널에서, Mac은 기본 터미널에서 실행한다.

bash
npm install -g @anthropic-ai/claude-code
  • 공식 문서: https://code.claude.com/docs/en/setup
  • 네이티브 설치·Homebrew·WinGet·로그인 안내 → Claude Code 설치 가이드

설치 후 확인:

bash
claude --version

처음 실행할 때는 아래 명령을 입력하고 화면 안내에 따라 로그인한다.

bash
claude

설치 확인 체크리스트 ​

세 도구가 모두 정상 설치되었는지 한 번에 확인한다.

bash
git --version     # Git Bash (Windows) / 기본 git (Mac)
node -v           # Node.js
npm -v            # npm (Node.js 동봉)
claude --version  # Claude Code

모든 명령에서 버전 번호가 출력되면 실습 환경 준비가 끝난 것이다.

자주 만나는 오류 ​

화면에 보이는 말뜻먼저 해볼 것
command not found: gitGit이 설치되지 않았거나 터미널이 Git Bash가 아니다Windows는 터미널을 Git Bash로 바꾸고, Mac은 git --version으로 확인
command not found: npmnpm이 설치되지 않았다Node.js를 설치한 뒤 npm -v 재확인
command not found: claudeClaude Code 명령을 찾지 못했다설치 후 터미널을 닫았다가 다시 열고 재시도

상세 가이드 목록 ​

  • Git Bash 설치 가이드 (Windows)
  • Node.js 설치 가이드 (Windows / Mac)
  • Claude Code 설치 가이드 (Windows / Mac)

KRoot-ADK 설치 및 사용 ​

앞의 세 도구(Git Bash · Node.js · Claude Code)가 준비되면 KRoot-ADK를 설치한다. kroot는 Claude Code를 KRoot 백엔드(프로젝트·세션·버전 관리)와 연동하고, 웹사이트 채팅으로 내 PC의 Claude Code를 사용할 수 있게 해주는 CLI다.

4. KRoot-ADK(kroot) 설치 ​

아래 한 줄로 설치한다. OS·아키텍처에 맞는 바이너리를 내려받아 설치한다.

bash
curl -fsSL https://kslaboratory.github.io/kroot-docs/install.sh | bash
옵션설명
(없음)사용자 홈에 설치 (기본)
--global시스템 전역(/usr/local/bin)에 설치
--version X.Y.Z특정 버전 설치

설치 후 확인:

bash
kroot --version

Windows는 Git Bash 터미널에서 실행한다. kroot: command not found가 뜨면 터미널을 닫았다 다시 연다.

5. 로그인 (kroot auth login) ​

kroot는 브라우저 로그인으로 개인 액세스 토큰(PAT)을 발급받아 저장한다. 비밀번호는 저장하지 않는다.

bash
kroot auth login
  1. 기본 브라우저가 열리며 인증 서버(https://auth.kroot.io)의 로그인 화면이 뜬다.
  2. 로그인하면 토큰이 발급되어 ~/.kroot/credential.json에 저장된다.
  3. 함께 서버 주소(grpcs://adk-server.kroot.io)와 채팅 릴레이 주소(wss://adk-relay.kroot.io/ws/agent)도 저장되어, 이후 명령은 옵션 없이 동작한다.

로그인 상태 확인:

bash
kroot auth whoami   # 서버가 토큰을 검증해 내 신원(이메일/ID)을 돌려준다

계정을 바꾸려면 kroot auth logout 후 다시 로그인한다.

6. 웹사이트에서 내 로컬 Claude Code 사용 (kroot chat start) ​

kroot chat start는 내 PC의 Claude Code를 릴레이 서버에 연결한다. 그러면 웹사이트 채팅창에 입력한 내용이 릴레이를 거쳐 내 PC의 Claude Code에서 실행되고, 응답이 다시 웹으로 돌아온다.

[웹 브라우저 채팅]  ──>  [릴레이 서버]  ──>  [내 PC의 kroot chat start = Claude Code]
        ^                                              |
        └──────────────  응답  ◀───────────────────────┘

실행:

bash
kroot chat start
  • relay 연결됨: wss://adk-relay.kroot.io/ws/agent 가 뜨면 연결 성공이다.
  • 이 상태에서 웹사이트에 같은 계정으로 로그인해 채팅을 열면, 메시지가 내 PC의 Claude Code로 전달된다.
  • 백그라운드 실행: kroot chat start --daemon, 중지: kroot chat stop (포그라운드는 Ctrl+C).

전제: kroot auth login이 되어 있어야 하고, Node.js가 설치돼 있어야 한다(채팅 실행기가 Node로 동작).

7. 프로젝트 생성과 세션 시작 (kroot init → claude) ​

7-1. 프로젝트 생성 ​

kroot init으로 새 프로젝트를 만든다. 프로젝트 폴더가 생성되고, 백엔드에 프로젝트가 등록·연결된다.

bash
kroot init myproject
  • 대화형으로 언어·백엔드 연동 등을 물어본다. 로그인이 안 돼 있으면 브라우저 로그인이 함께 진행된다.
  • 완료되면 myproject/ 폴더에 .claude/, .kroot/, CLAUDE.md 등이 생성되고, 이 폴더가 백엔드 프로젝트와 링크된다.

7-2. 프로젝트로 이동해 세션 시작 ​

bash
cd myproject
claude
  • 그 폴더에서 처음 claude를 실행하면 신뢰(trust) 여부를 묻는다. 1(Yes)을 선택한다.
  • (IDE로 폴더를 먼저 열면 이 다이얼로그가 안 뜰 수 있으니, 순수 터미널에서 먼저 claude를 실행하는 것을 권한다.)

7-3. 프롬프트 입력 ​

세션이 열리면 만들고 싶은 것을 자연어로 입력한다.

> 온라인 서점 웹사이트를 만들어줘. 도서 목록, 장바구니, 주문 기능이 필요해.
  • KRoot 오케스트레이터(J.A.R.V.I.S.)가 요구사항 분석 → ERD → 화면 설계 → 구현 → 배포까지 단계별 파이프라인으로 진행하며, 각 단계 산출물이 백엔드에 저장된다.
  • 만들어진 대화·산출물은 kroot가 백엔드와 동기화하므로, 웹에서도 진행 상황을 확인할 수 있다.

전체 흐름 한눈에 보기 ​

bash
# 1) 설치
curl -fsSL https://kslaboratory.github.io/kroot-docs/install.sh | bash

# 2) 로그인 (브라우저 인증)
kroot auth login

# 3) (선택) 웹 채팅용 로컬 연결
kroot chat start

# 4) 프로젝트 생성 → 세션 → 프롬프트
kroot init myproject
cd myproject
claude
# > "이런저런 내용의 프로젝트를 만들어줘"

PAT expired or invalid저장된 토큰이 만료/무효kroot auth login 재실행
relay 연결 실패: … 404릴레이 주소에 경로가 빠짐--relay wss://…/ws/agent 처럼 /ws/agent를 포함해 지정
relay 인증 실패 — 토큰이 만료/무효릴레이가 토큰을 거부kroot auth login으로 재인증
this workspace has not been trusted프로젝트 신뢰 전 상태그 폴더에서 터미널로 claude 실행 후 신뢰 수락

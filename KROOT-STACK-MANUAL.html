KRoot 스택 사용 매뉴얼 ​

kroot-proto · kroot-server · kroot-adk 의 설치 · 설정 · 실행 · 연동을 한 번에 다루는 사용자/운영자 매뉴얼. 최종 갱신: 2026-06-25

1. 개요 ​

KRoot 스택은 레거시 현대화를 위한 AI 에이전트 개발 키트로, 4개의 구성요소가 함께 동작합니다.

구성요소역할언어/기술위치
kroot-adk개발자 CLI(kroot) + Claude Code 훅·템플릿Go 1.25github.com/kslaboratory/kroot-adk
kroot-server백엔드 gRPC/REST API (프로젝트·대화·산출물 저장)Go 1.25github.com/kslaboratory/kroot-server
kroot-protogRPC API 계약(.proto + 생성 코드) — CLI·서버 공유Protobuf + Gogithub.com/kslaboratory/kroot-proto
인증 서버 (의존)PAT(kpat_) 발급·검증 (OAuth2/PKCE)Spring (별도)kroot/backend/server/auth (포트 17020)

아키텍처 / 데이터 흐름 ​

            ┌──────────────┐   브라우저 로그인(OAuth2+PKCE)    ┌─────────────────────┐
   사용자 ──▶│  kroot (CLI) │ ───────────────────────────────▶│  인증 서버 :17020     │
            │  kroot-adk   │◀── PAT(kpat_) 발급 ──────────────│  (Spring, OAuth2 AS)  │
            └──────┬───────┘                                  └──────────┬──────────┘
                   │ gRPC :4500 (Bearer kpat_)                           │ introspection
                   ▼                                                     │ (M2M)
            ┌──────────────┐   PAT 검증 위임 ──────────────────────────────┘
            │ kroot-server │
            │   :4500 gRPC │── Postgres(kroot DB / kroot_app 스키마)
            │   :4501 REST │── MinIO/S3 (파일 산출물)
            └──────────────┘
                   ▲
                   │ 둘 다 import
            ┌──────────────┐
            │  kroot-proto │  (gRPC 계약: proto → 생성 Go 코드)
            └──────────────┘
  • kroot-adk(CLI) 는 DB에 직접 접근하지 않습니다. 모든 작업은 kroot-server gRPC를 통합니다.
  • 인증은 PAT 전용입니다. CLI가 브라우저 로그인으로 PAT(kpat_…)를 받아 저장하고, 매 gRPC 호출에 Bearer로 싣습니다. kroot-server는 그 PAT를 인증 서버(17020) introspection으로 검증합니다.
  • kroot-proto 는 계약(SSOT)이며, kroot-adk·kroot-server가 go.mod replace로 로컬 디렉터리를 참조합니다.

3. 빠른 시작 (로컬 전체 스택) ​

아래 순서대로 진행합니다: 레포 클론 → proto 생성 → 인프라 → 인증 서버 → kroot-server → CLI.

3.0 레포 클론 (형제 디렉터리로) ​

go.mod replace ../kroot-proto 때문에 네 레포는 같은 부모 폴더 아래 형제로 둬야 합니다.

bash
mkdir -p ~/Dev/kaonsoftlab && cd ~/Dev/kaonsoftlab
git clone https://github.com/kslaboratory/kroot-proto.git
git clone https://github.com/kslaboratory/kroot-server.git
git clone https://github.com/kslaboratory/kroot-adk.git
# 인증 서버(Spring)는 kroot 모노레포에 있음
git clone https://github.com/kslaboratory/kroot.git   # (접근 권한 필요)

bash
cd kroot-proto
buf generate          # proto/kroot/v1/*.proto → gen/kroot/v1/*.pb.go

bash

4. kroot-proto (gRPC 계약) ​

역할 ​

CLI ↔ 서버 사이의 gRPC API 계약 단일 진실 원천(SSOT). 비즈니스 로직·DB·시크릿 없음, 메시지/서비스 형태만 정의.

구성 ​

  • proto/kroot/v1/*.proto — 23개 정의 파일, 패키지 kroot.v1
  • gen/kroot/v1/*.pb.go, *_grpc.pb.go, *.pb.gw.go — 생성 코드
  • gen/openapi/kroot_v1.swagger.json — REST(OpenAPI v2) 스펙
  • 주요 서비스(22개): AuthService(WhoAmI만), ProjectService, WorkflowService, OutputService, SessionService, ConversationService, SpecService, DesignService, EventStormingService, Backend/Frontend/Html/Test/UsecaseStageService, WireframeService, TodoService, LocalWorkspaceService, 각종 *VersionService 등

빌드/재생성 ​

bash
buf generate     # 코드 생성 (buf.gen.yaml)
buf lint         # 린트 (buf.yaml, STANDARD 룰셋)
  • 툴체인: buf (buf.yaml, buf.gen.yaml). 별도 Makefile 없음.
  • 플러그인: protocolbuffers/go, grpc/go, grpc-gateway, openapiv2 (BSR 원격).

소비 방식 ​

kroot-adk·kroot-server 양쪽 go.mod:

require github.com/jikime/kroot-proto v0.0.0
replace github.com/jikime/kroot-proto => ../kroot-proto

→ 로컬 형제 디렉터리를 참조. proto 재생성 시 양쪽에 즉시 반영(모노레포식 개발). 현재 게시된 태그 버전 없음.

인증 관련 주의: AuthService는 WhoAmI RPC만 남았습니다. Login/Refresh/Logout RPC는 PAT 전용 전환으로 제거됐습니다.

5. kroot-server (백엔드) ​

역할 / 구조 ​

  • kroot-adk CLI의 백엔드. gRPC :4500 + grpc-gateway REST :4501 (동일 서비스 구현 공유).
  • Clean Architecture: rpc/ → usecase/ → repository/postgres/.
  • 엔트리: cmd/kroot-server/main.go, 초기화: internal/server/server.go.

의존 인프라 ​

인프라용도설정
PostgreSQL프로젝트·대화·산출물 데이터KROOT_DB_URL (스키마 kroot_app)
MinIO/S3파일 산출물(와이어프레임·디자인·스테이지 파일)KROOT_S3_*
인증 서버(17020)PAT introspectionKROOT_AUTH_ISSUER + KROOT_AUTH_CLIENT_SECRET

환경변수 (internal/server/config/config.go) ​

.env.local 자동 로드(godotenv) → 실제 환경변수가 우선.

변수기본값필수설명
KROOT_HOST127.0.0.1바인드 주소
KROOT_GRPC_PORT4500gRPC 포트
KROOT_REST_PORT4501REST(gateway) 포트
KROOT_DB_URL—✅예: postgresql://kroot:비번@localhost:17000/kroot?search_path=kroot_app&sslmode=disable
KROOT_AUTH_ISSUER—✅인증 서버 origin (예: http://localhost:17020)
KROOT_AUTH_CLIENT_IDkroot-serverM2M 클라이언트 ID
KROOT_AUTH_CLIENT_SECRET—✅M2M 시크릿 (인증 서버 등록값과 일치)
KROOT_S3_ENDPOINT—✅예: localhost:9000
KROOT_S3_ACCESS_KEY / KROOT_S3_SECRET_KEY—✅MinIO 자격증명
KROOT_S3_BUCKETkroot-files버킷명
KROOT_MAX_UPLOAD_MB32업로드 상한(MB)
KROOT_LOG_LEVELinfo로그 레벨

검증: KROOT_DB_URL, KROOT_AUTH_ISSUER, KROOT_AUTH_CLIENT_SECRET, KROOT_S3_* 누락 시 시작 실패. gRPC·REST 포트는 서로 달라야 함.

.env.local 예시:

env
KROOT_HOST=127.0.0.1
KROOT_GRPC_PORT=4500
KROOT_REST_PORT=4501
KROOT_DB_URL=postgresql://kroot:kroot_dev_password_change_me@localhost:17000/kroot?search_path=kroot_app&sslmode=disable
KROOT_S3_ENDPOINT=localhost:9000
KROOT_S3_ACCESS_KEY=...
KROOT_S3_SECRET_KEY=...
KROOT_S3_BUCKET=kroot-files
KROOT_AUTH_ISSUER=http://localhost:17020
KROOT_AUTH_CLIENT_SECRET=kroot_server_secret_change_me
KROOT_LOG_LEVEL=debug

인증 모델 (PAT 전용) ​

  • 모든 RPC가 인증 대상(공개 메서드 없음). Authorization: Bearer kpat_… 헤더 필요.
  • internal/server/interceptor/auth.go 가 토큰 추출 → internal/server/auth/spring_pat.go(SpringPATVerifier)가 인증 서버 /api/internal/pat/introspect(M2M client_credentials)로 검증.
  • introspection 결과(userId·email·name·scopes)를 Claims로 만들어 context 주입. userId가 곧 Subject(= 프로젝트 owner_id 등에 저장됨). 결과는 60초 캐시.

실행 / 헬스 ​

bash
go build -o bin/kroot-server ./cmd/kroot-server
./bin/kroot-server
엔드포인트(REST :4501)용도
GET /readyzDB 핑 포함 준비 상태
GET /api/v1/auth/configCLI가 issuer·client·scope 를 자동 발견하는 디스커버리

DB 스키마: kroot-server는 마이그레이션을 관리하지 않습니다. 스키마는 kroot_app 스키마에 적재돼 있어야 합니다(정본: kroot/frontend/clients/kroot-main-site/prisma/kroot-app-schema.sql).

6. kroot-adk (CLI) ​

역할 ​

개발자 CLI(kroot) + kroot-wt(git worktree 헬퍼). Claude Code 훅·템플릿·에이전트·스킬을 프로젝트에 설치하고, 13단계 파이프라인(S0~S12)을 오케스트레이션.

설치 (git clone → 빌드) ​

소스 빌드는 kroot-proto 가 형제 디렉터리에 있어야 합니다(go.mod replace ../kroot-proto). 아래 2장의 "레포 클론"을 먼저 수행하세요.

bash
git clone https://github.com/kslaboratory/kroot-proto.git   # (이미 클론했다면 생략)
git clone https://github.com/kslaboratory/kroot-adk.git
cd kroot-adk
make build      # dist/kroot (+ dist/kroot-wt) 생성
make install    # $(go env GOPATH)/bin 에 설치 → PATH 에 있으면 `kroot` 사용 가능
# 또는 make 없이:
go build -o dist/kroot ./cmd/kroot

설치 확인:

bash
kroot --version

인증 ​

bash
kroot auth login              # 브라우저 OAuth2+PKCE → PAT(kpat_) 발급 → ~/.kroot/credential.json(0600)
kroot auth login --token kpat_…   # CI/자동화 (또는 KROOT_TOKEN 환경변수)
kroot auth whoami             # 서버가 introspection으로 해소한 신원 출력
kroot auth status             # 로그인/만료 상태
kroot auth logout             # 자격증명 삭제(+서버 revoke 시도)
kroot auth token              # bearer 토큰 출력(MCP/스크립트용)
  • 기본 issuer http://localhost:17020, 클라이언트 kroot-cli-app(공개, PKCE), 콜백 http://127.0.0.1:17298/callback.
  • PAT 만료 90일, 이름 cli@<hostname>. 재로그인 시 같은 이름 PAT는 자동 revoke 후 재발급(쿼터 보호).

주요 환경변수 ​

변수기본값설명
KROOT_SERVERgrpc://127.0.0.1:4500백엔드 gRPC 주소
KROOT_AUTH_ISSUERhttp://localhost:17020인증 서버
KROOT_TOKEN—CI용 PAT(kpat_…)
KROOT_HOME~/.kroot자격증명 저장 위치 override

사용 흐름 ​

bash
cd /path/to/legacy-project
kroot init        # .kroot/·.claude/ 생성, 템플릿·훅 설치, 백엔드 연동(브라우저 로그인 유도)
kroot link        # (선택) 기존 원격 프로젝트에 연결 또는 신규 생성
claude            # Claude Code 세션 — 훅이 대화/산출물/세션을 kroot-server에 자동 동기화
kroot doctor      # 환경·도구·프로젝트 구조 점검
kroot status      # 현재 상태

명령어 요약 (cmd/root.go) ​

  • 핵심: init, status, doctor, link, auth, update
  • 산출물/스테이지: conversations, spec, wireframe, usecase-stage, eventstorming, design, html-stage, frontend-stage, backend-stage, test-stage
  • 버전 스냅샷: init-version, requirement-version, spec-version, erd-version
  • 유틸/통합: hooks(Claude Code 훅), workflow, router(LLM 프로바이더 라우팅), skill, tag, language, lsp-setup, statusline, worktree

13단계 파이프라인 (S0~S12) ​

S0 초기화 · S1 요구사항 · S2 기능정의 · S3 ERD · S4 와이어프레임 · S5 유즈케이스 · S6 이벤트스토밍 · S7 디자인 · S8 HTML · S9 Frontend · S10 Backend · S11 Test · S12 배포/품질. Claude Code 안에서 자연어/슬래시 명령으로 단계 실행.

7. 연동 흐름 (요약) ​

  1. 계약: kroot-proto가 gRPC 서비스/메시지를 정의 → kroot-adk(클라이언트 스텁)·kroot-server(서버 구현)가 동일 계약 사용(go.mod replace).
  2. 인증: kroot auth login → 브라우저로 인증 서버(17020) 로그인 → /api/me/credentials에서 PAT 발급 → ~/.kroot/credential.json 저장. (OAuth access token은 PAT 발급에만 쓰고 버림)
  3. 호출: CLI가 매 gRPC 호출에 Bearer kpat_… 첨부 → kroot-server 인터셉터가 인증 서버 introspection으로 검증 → userId를 Subject로 context 주입.
  4. 데이터: 핸들러가 Subject(=auth 사용자 id)로 작업 데이터 저장. 프로젝트는 projects.owner_id = Subject. 저장소는 Postgres kroot_app 스키마 + MinIO 버킷.
  5. 훅 동기화: Claude Code 훅(kroot hooks …)이 대화 턴(ConversationService)·산출물(OutputService)·세션(SessionService)을 자동 push.

8. 트러블슈팅 ​

증상원인 / 해결
invalid token: ... invalid number of segmentskpat_ 토큰이 JWT로 파싱됨 = kroot-server에 PAT 검증이 꺼짐. KROOT_AUTH_ISSUER·KROOT_AUTH_CLIENT_SECRET를 .env.local에 설정하고 재기동. 시작 로그 PAT introspection enabled 확인
personal access token rejected (expired or revoked)서버가 PAT에 Unauthenticated 반환. 인증 서버 introspection 실패(M2M 시크릿 불일치) 또는 PAT 만료. kroot auth login 재실행
PAT endpoint returned 409PAT 쿼터 초과(기본 5). 재로그인은 같은 이름 PAT를 revoke 후 재발급하므로 보통 자동 해소. 아니면 /api/me/credentials에서 정리
projects_owner_id_fkey (23503)(구버전) owner_id FK 위반. 현재는 PAT의 auth 사용자 id를 owner_id로 저장
브라우저가 안 열림 / 포트 17298 점유콜백 포트 고정. 점유 시 해제 후 재시도. CI는 --token/KROOT_TOKEN 사용
kroot doctor 로 환경 점검Go·도구·프로젝트 구조·언어 SDK 진단
